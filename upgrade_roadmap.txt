PART 3 — SCALING TO 10k+ USERS (infra, not code)
================================================================================

The architecture is scale-friendly in shape. What breaks at 10k users is the
reliance on free/shared external services on the hot path. All code-level
scale features (v2) are complete — what remains is infra.

[SCALE-4] Infrastructure: leave the free tier.
  - Express + FastAPI: paid, always-on, horizontally scaled behind a load
    balancer (autoscale on CPU/queue depth). FastAPI is already stateless.
  - SSE at scale: cap concurrent streams per instance; ensure LB doesn't
    buffer; connection limits matter.
  - MongoDB: M0 → M10+ with proper sizing. Indexes already good. Add read
    replica for history + ownership lookups; tune Mongoose maxPoolSize.

[SCALE-8] Shared rate-limit store (the moment there's a second instance).
  express-rate-limit's default store is in-memory per-process — two instances
  means a user gets 2× the intended limit. Fix: back with Redis
  (rate-limit-redis / Upstash). This is the ONLY per-instance state blocking
  horizontal scaling.

[SCALE-9] Secrets manager instead of per-service .env files.
  Move HF_TOKEN, JWT_SECRET, MONGO_URI, etc. into Doppler / AWS Secrets
  Manager / Render env groups with rotation.

PART 4 — WIRING GAPS (code exists, not yet connected)
================================================================================

These modules are implemented but need to be wired into the main flow:

  [WIRE-1] ResilientLLM as default
    get_resilient_llm() exists in llm_backend.py but main.py still calls
    get_llm_backend(). Swap to enable circuit breaker + auto-fallback.

  [WIRE-2] Egress allowlist on all httpx clients
    egress_allowlist.py has check_url() and httpx_event_hook() but they're
    not attached to the AsyncClients in sources/ (pubmed, openalex, trials,
    geocode).

  [WIRE-3] Event buffer in streaming pipeline
    event_buffer.py works for the /jobs path but /pipeline/stream doesn't
    call buffer_event(). SSE replay on reconnect only works via the job API.

  [WIRE-4] Cost + TTFT metrics in pipeline
    record_ttft() and record_tokens() exist in observability.py but aren't
    called from pipeline stages. Only record_message() is wired.

  [WIRE-5] Queue-depth through Express health proxy
    FastAPI /health returns queue_depth but Express /health doesn't proxy it.
    Load test confirmed: has_queue_depth=false.

  [WIRE-6] Token-aware rate limit default
    DAILY_TOKEN_CAP defaults to 0 (disabled). Works when set but not on by
    default. Decide a sensible default once usage patterns are known.

  [WIRE-7] PII redactor scope
    Only applied to observability spans. Not applied to stored messages or
    cache entries.
